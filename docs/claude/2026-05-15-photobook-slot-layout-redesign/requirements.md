# Product Requirements

## 1. Page Types

The photobook has three page categories:

1. Cover
2. Content pages
3. Back cover

Preview and PDF order must always be:

1. Cover
2. Content page 1...N
3. Back cover

The editor should also show cover as the first page and back cover as the last page.

## 2. Cover And Back Cover

First phase:

- Cover supports editable text only.
- Back cover supports editable text only.
- Cover/back cover do not support image placement.
- Cover/back cover must be included in preview and PDF.
- Cover/back cover should use the existing visual style already introduced for the app.

## 3. Content Page Templates

Support four fixed templates:

- `Single`: one image slot.
- `TwoHorizontal`: two image slots stacked top/bottom.
- `TwoVertical`: two image slots side by side.
- `GridFour`: four image slots in a 2x2 grid.

Each slot has a fixed rectangle generated by the layout engine. Users adjust image crop inside the slot, not the slot itself.

## 4. Default Import

When importing from memories:

- Import at the photo level.
- If the user selects an entire memory with 5 photos, create 5 content pages.
- If the user selects 2 photos from that memory, create 2 content pages.
- Each imported photo creates a `Single` template page.
- Image placement defaults to proportional scaling and centered crop/fit inside its slot.
- Do not auto-pack multiple imported photos into one page.

## 5. Memory Photo Picker

The picker must support two modes:

### Batch Import Mode

Used by "add photo/import from memory":

- Show memory list.
- Each memory item shows cover thumbnail, mood text/date if available, and photo count.
- User can select an entire memory.
- User can open a memory and select individual photos.
- Multiple photos can be selected.
- Result is a list of selected photos.

### Single Slot Mode

Used by clicking an empty slot or replacing a slot image:

- User selects exactly one photo.
- User can enter a memory and choose one photo.
- "Select entire memory" should not fill the current slot directly. Either hide it or route the user to batch import.

## 6. Template Switching

Changing a page template must not automatically absorb photos from following pages.

Rules:

- `Single -> TwoHorizontal`, `Single -> TwoVertical`, or `Single -> GridFour`: keep the original image in slot 1; other slots are empty.
- Switching from a template with fewer slots to more slots: keep existing images by slot order.
- Switching from a template with more slots to fewer slots:
  - If the number of filled slots is less than or equal to the new slot count, keep them by order.
  - If there are more filled slots than the new template can hold, show a confirmation dialog.

Recommended dialog actions:

- Keep selected image.
- Keep first N images and move extra images to new `Single` pages.
- Cancel.

## 7. Moving Photos Between Pages

User moves photos by selecting a slot image, then using commands.

Required commands:

- Move to previous page.
- Move to next page.
- Move to new page.
- Move to a chosen page.

Target behavior:

- If target page has an empty slot, place image in the first empty slot by slot order.
- If target page is full, show a dialog:
  - Replace a selected target slot.
  - Change target page template.
  - Move image to a new page.
  - Cancel.
- Source slot becomes empty after a successful move.
- If source page becomes empty, do not delete the source page automatically.

## 8. Swapping Photos In The Same Page

User can reorder photos inside a multi-slot page:

1. Select a filled slot.
2. Tap "swap position".
3. Tap another slot on the same page.
4. The two slots exchange image references and crop parameters.

## 9. Manual Crop And Zoom

For each slot image:

- User can drag image inside the slot.
- User can pinch/zoom image inside the slot.
- The image cannot visually escape the slot bounds.
- The saved values are stored per slot:
  - `cropScale`
  - `cropOffsetX`
  - `cropOffsetY`
- Save behavior should match current editor expectation: user adjustments are persisted when the user taps Save.
- Preview and PDF must render the same crop/zoom state.

## 10. Preview

Keep current orientation behavior:

- Portrait: one page.
- Landscape: two joined pages.

Additional requirements:

- Initial page is cover.
- Last page is back cover.
- Interior landscape pages should appear as joined spreads, not separated cards.
- Navigation must not jump back to the cover after moving to page 2.

## 11. PDF Export

PDF export must use the same page order and layout engine:

1. Cover.
2. Content pages.
3. Back cover.

Exported content pages must match editor/preview slot positions, crop, zoom, safe margins, and bleed behavior.

## 12. Persistence

No backward compatibility is required.

Use the new page layout document model for saved content pages. Existing test data can be discarded by uninstalling/reinstalling the app.
